Backpropagating through a random draw

VI by hand wrote each draw as $m + s\cdot\eps$ without comment. The VAE loss also uses a $z$ drawn from the encoder's cloud, and to train the encoder, gradients must get from the loss back to $\mu$ and $\sigma$ through that draw. Here is why the way we write the draw is the whole trick.

The problem

A sampling step sits in the middle of the graph

In PyTorch, Normal(mu, sigma).sample() returns a tensor with no gradient history: the graph is cut at z.

We want the gradient of the expected loss with respect to μ and σ: if the cloud moves a little, how does the average loss change? There are other estimators (score function / REINFORCE), but they are noisy. Here is a simple trick that works for Gaussians.

The trick

Draw standard noise first, then stretch and shift it

$$z = \mu + \sigma\,\eps,\quad \eps\sim\N(0,1) \qquad\Longrightarrow\qquad z \sim \N(\mu,\sigma^2)$$

Same distribution as before (the $\mu = 1$, $\sigma = 0.5$ cloud of the Gaussian KL slide). But the randomness now enters as an input, $\eps$, that does not depend on any weights.

Follow one dot (red): ε = −0.4, scaled by σ = 0.5 to −0.2, shifted by μ = 1 to 0.8. Each z is a deterministic function of (μ, σ, ε).

If μ increases a little, every dot moves right by the same amount. If σ increases, each dot moves away from the centre in proportion to its ε. That is exactly the derivative.

The fix

Now the path from the loss to $\mu$ and $\sigma$ is ordinary arithmetic

Formally: ∇ E_{z∼q}[f(z)] = E_{ε∼𝒩(0,1)}[∇ f(μ + σε)], under mild regularity conditions. We check this numerically a few slides from now.

Chain rule, symbol by symbol

Take $f(z) = z^2$ as the loss

$$z = \mu + \sigma\eps \qquad\Rightarrow\qquad \frac{\partial z}{\partial \mu} = 1, \qquad \frac{\partial z}{\partial \sigma} = \eps, \qquad \frac{\partial f}{\partial z} = 2z$$
$$\frac{\partial f}{\partial \mu} = \frac{\partial f}{\partial z}\cdot\frac{\partial z}{\partial \mu} = 2z\cdot 1$$
$$\frac{\partial f}{\partial \sigma} = \frac{\partial f}{\partial z}\cdot\frac{\partial z}{\partial \sigma} = 2z\cdot\eps$$

The noise value $\eps$ appears in the $\sigma$-gradient: a draw far from the centre pushes $\sigma$ harder.

ε is treated exactly like an input pixel: a fixed number for this forward and backward pass. A new ε is drawn next step.

Now plug in numbers

$\mu = 1,\ \sigma = 0.5,\ \eps = -0.4$

Finite-difference check with ε held fixed: μ → 1.001 gives z = 0.801 and f = 0.641601, slope 1.601 ≈ 1.6. If you resample ε between the two evaluations, the check becomes noise.

One more link in the chain

The network outputs $v = \log\sigma^2$, not $\sigma$

$\sigma$$=$$e^{v/2}$ $v$ can be any real number; $\sigma$ is always positive $\dfrac{\partial\sigma}{\partial v}$$=$$\tfrac12 e^{v/2} = \dfrac{\sigma}{2} = 0.25$ derivative of $e^{v/2}$ $\dfrac{\partial f}{\partial v}$$=$$\dfrac{\partial f}{\partial \sigma}\cdot\dfrac{\partial\sigma}{\partial v} = -0.64 \times 0.25 = -0.16$ one more chain-rule factor

Autograd does exactly this. The point of doing it by hand once: no step is magic.

Is one draw enough?

One draw is noisy; the average is exactly right

$$\E_\eps\big[f\big] = \E\big[(\mu+\sigma\eps)^2\big] = \mu^2 + \sigma^2 \quad\Rightarrow\quad \frac{\partial}{\partial\mu}\E[f] = 2\mu = 2, \qquad \frac{\partial}{\partial\sigma}\E[f] = 2\sigma = 1$$

Our single $\eps$ gave 1.6 and $-0.64$. Averaged over {{rep_grad.n}} draws: {{rep_grad.mean_mu}} and {{rep_grad.mean_sd}}. SGD only needs the right answer on average.

Each histogram: the per-sample gradient for 10,000 values of ε. The red dashed line is our ε = −0.4. The solid line, the average, sits on the exact gradient of the expected loss. Noisy but unbiased: exactly what stochastic gradient descent needs.

In PyTorch

Three lines

# encoder outputs, shape [B, 2] each
mu, logvar = encoder(x)
std = torch.exp(0.5 * logvar)     # sigma = exp(v / 2)
eps = torch.randn_like(std)       # standard normal, no grad
z   = mu + std * eps              # differentiable in mu, std

Why output $\log\sigma^2$? It can be any real number; $\sigma$ must be positive.

Normal(mu, std).rsample() does the same thing; .sample() drops the gradient.

For our 3: $\mu = ({{our3.mu.0}},\, {{our3.mu.1}})$, $\eps = ({{our3.eps.0}},\, {{our3.eps.1}})$ gives $z = ({{our3.z.0}},\, {{our3.z.1}})$.

Common bug: using exp(logvar) where the standard deviation is needed, which squares σ. Another: calling .sample() and wondering why the encoder never learns.

What we did, and what comes next

What we did

  1. Sampling $z$ directly cuts the gradient path to $\mu$ and $\sigma$.
  2. Write $z = \mu + \sigma\eps$ with $\eps \sim \N(0, 1)$: same distribution, randomness as an input.
  3. $\partial z/\partial\mu = 1$, $\partial z/\partial\sigma = \eps$; one draw is noisy, the average is exact.
  4. In PyTorch: three lines, or rsample().
