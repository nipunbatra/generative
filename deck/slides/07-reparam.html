Backpropagating through the encoder's random draw

VI by hand drew each code as $m + s\cdot\eps$ and backpropagated through it: the VI lecture's reparameterisation trick (its Part 5). The VAE does the same, except that $\mu$ and $\sigma$ come out of the encoder, as $\log\sigma^2$. One recalled picture, one more link in the chain, and three lines of PyTorch.

From the VI lecture, Part 5, with the encoder in front

Draw $\eps$ first, and the path back to $\mu$ and $\sigma$ is arithmetic

As the VI lecture showed, sample() would cut the graph at $z$. Each draw gives a noisy gradient; on average it is exact.

VI lecture (vi.html), Part 5: the blocked graph · sample() fails · the reparameterised graph · checked in code · rsample

In the VI lecture, loc and scale were the two parameters of one q. Here μ and σ are outputs of the encoder, so the gradient continues past them into the encoder's weights. f stands for the loss: reconstruction plus KL.

Formally: ∇ E_{z∼q}[f(z)] = E_{ε∼𝒩(0,I)}[∇ f(μ + σε)]. A single ε gives a noisy but unbiased gradient, which is all stochastic gradient descent needs.

What the encoder adds: one more link in the chain

The encoder outputs $v = \log\sigma^2$, not $\sigma$

$\sigma$$=$$e^{v/2}$ $v$ can be any real number; $\sigma$ is always positive $\dfrac{\partial\sigma}{\partial v}$$=$$\tfrac12 e^{v/2} = \dfrac{\sigma}{2}$ derivative of $e^{v/2}$ $\dfrac{\partial z}{\partial v}$$=$$\dfrac{\partial z}{\partial\sigma}\cdot\dfrac{\partial\sigma}{\partial v} = \eps\cdot\dfrac{\sigma}{2}$ one more chain-rule factor after $\partial z/\partial\sigma = \eps$ $\dfrac{\partial z_1}{\partial v_1}$$=$${{our3.eps.0}} \times \dfrac{ {{our3.sigma.0}} }{2} = {{rep_dzdv}}$ our 3: $v_1 = {{our3.logvar.0}}$, so $\sigma_1 = {{our3.sigma.0}}$; this draw's $\eps_1 = {{our3.eps.0}}$

Autograd adds this factor for us: in code it is the one line std = torch.exp(0.5 * logvar).

The numbers are our 3's first coordinate, with the same draw as Part 7's sampling step. The factor is small because σ is small: a cloud 0.05 wide hardly moves its draws when its log-variance changes a little.

The full gradient for v₁ multiplies this by ∂loss/∂z₁ from the decoder, and adds the KL term's own derivative, ½(σ₁² − 1).

In PyTorch

Three lines

# encoder outputs, shape [B, 2] each
mu, logvar = encoder(x)
std = torch.exp(0.5 * logvar)     # sigma = exp(v / 2)
eps = torch.randn_like(std)       # standard normal, no grad
z   = mu + std * eps              # differentiable in mu, std

std is $\sigma = e^{v/2}$: the extra link from the last slide.

Normal(mu, std).rsample() does the same thing, as in the VI lecture; .sample() drops the gradient.

For our 3: $\mu = ({{our3.mu.0}},\, {{our3.mu.1}})$, $\eps = ({{our3.eps.0}},\, {{our3.eps.1}})$ gives $z = ({{our3.z.0}},\, {{our3.z.1}})$.

Common bug: using exp(logvar) where the standard deviation is needed, which squares σ. Another: calling .sample() and wondering why the encoder never learns.
