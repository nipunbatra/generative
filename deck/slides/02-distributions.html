Part 1

What does it mean to learn a distribution?

Before images, one number. Everything we need (fitting, sampling, hidden causes, inference) fits on a number line.

Our 1-D toy data

200 numbers in two clumps

Pretend each number is an image squashed to one value. How would you produce a 201st that looks like it belongs?

Data: 200 draws, half from 𝒩(−2, 0.5²) and half from 𝒩(2, 0.5²). Students do not need to know that yet; they should see two clumps.

Typical answers: "pick a random existing point" (memorising, no new data), "use the average" (next slide), "fit a distribution and sample" (yes).

A tempting answer

The average is a terrible sample

A model that predicts the mean always outputs something that never occurs. Regression thinking does not give generation.

This is why "train a network with MSE to output an image" gives blurry averages. We will see a softer version of this later when VAE samples look blurry.

Fit, then sample

The best single Gaussian, by maximum likelihood

$$\hat\mu = \frac1N\sum_{i=1}^{N} x_i = {{toy.mean}} \qquad \hat\sigma^2 = \frac1N \sum_{i=1}^{N} (x_i-\hat\mu)^2 = {{toy.var}}$$
$$x_{\text{new}} = \hat\mu + \hat\sigma\,\eps,\quad \eps \sim \N(0,1)$$

These two numbers make the observed data as probable as any Gaussian can.

{{toy.gauss_samples_in_gap}} of 30 samples land in the empty gap. Best fit within the family, wrong shape.

The maximum-likelihood Gaussian has the sample mean and the 1/N variance. Students derived this in the probability lectures.

Lesson: optimisation worked perfectly; the model family was too simple. Better optimisation cannot fix that.

A richer model: tell a story

Hidden choice first, then the number

The coin is never written down in the data. We only ever see $x$. The coin $z$ is a hidden (latent) variable.

Read the sampling recipe aloud: flip a coin, pick that bump, draw a point from it. Two simple steps make a two-bump distribution that one Gaussian could not.

This "generative story" pattern is exactly the VAE: first draw a hidden code z, then draw the image x given z.

One ingredient, worked by hand

How high is bump B at $x = 1.5$?

$$\N(x;\mu,\sigma^2) = \frac{1}{\sigma\sqrt{2\pi}}\,\exp\!\Big(-\frac{(x-\mu)^2}{2\sigma^2}\Big)$$
$$\frac{x-\mu}{\sigma} = \frac{1.5 - 2}{0.5} = -1$$
$$\exp\!\big(-\tfrac12\cdot(-1)^2\big) = e^{-0.5} = {{gauss_15.expo}}$$
$$\frac{1}{0.5\sqrt{2\pi}} = {{gauss_15.norm}} \qquad\Rightarrow\qquad {{gauss_15.norm}}\times{{gauss_15.expo}} = \mathbf{ {{gauss_15.value}} }$$

A density is a height, not a probability: it can exceed 1 for a narrow bump. Only areas are probabilities.

The formula has two parts: how many standard deviations away x is (squared, inside the exponent), and a constant that makes the area under the curve 1.

One standard deviation from the centre always gives e^{−1/2} ≈ 0.61 of the peak height.

From the story to a probability

To score $x$, add over every hidden value

$$p(x) = \sum_{z\in\{\mathrm{A},\mathrm{B}\}} \cz{p(z)}\,\cdec{p(x\mid z)} = \tfrac12\,\N(x;-2,0.5^2) + \tfrac12\,\N(x;\,2,0.5^2)$$
$$\text{at } x=1.5:\quad \tfrac12\cdot 0.000 + \tfrac12\cdot {{gauss_15.value}} = 0.242$$

Samples now fall in the bumps. Remember this sum. With images it becomes an integral we cannot compute.

The A-bump contributes about 2 × 10⁻¹² at x = 1.5: 7 standard deviations away.

"Marginalising out z": the probability of what we observe is an average over everything we cannot observe.

Bayes' rule is just this table: multiply, then divide by the total. $x = 0.1$ is close to the middle, so we stay unsure.

Build by build: the two likelihoods (both tiny: 0.1 is far from both centres, but closer to B), multiply by the prior, add to get the evidence, divide.

The tiny numbers do not matter: only their ratio does. This will matter for images, where likelihoods are like 10⁻⁵⁰.

Do it for every $x$

The posterior, as a curve

Repeat the table for every $x$ and plot $p(\mathrm{B}\mid x)$.

Far right: certainly B. Far left: certainly A. Near 0: unsure.

For these two bumps the curve is exactly $\mathrm{sigmoid}(16x)$: a logistic regression in disguise.

Going from an observation back to its hidden cause is called inference. The VAE's encoder will learn to do it.

Derivation of the sigmoid if asked: the log ratio of the two likelihoods is [(x+2)² − (x−2)²]/(2·0.25) = 16x, and the equal priors cancel.

Here inference is exact because we can compute p(x). For images, p(x) is the hard part, so the posterior will be hard too.

Four words we will use all lecture

Prior, likelihood, evidence, posterior

namesymbolquestion it answersat $x = 0.1$

Bayes ties them together: posterior = prior × likelihood ÷ evidence.

Keep these four colours in mind: amber for z and the prior, teal for the decoder/likelihood, blue for observed data, purple for the encoder/posterior.

From a coin to a code

The same story for images

The code is 2 real numbers instead of a coin, and a network maps it to 784 pixel probabilities. Nobody tells it what $z$ means.

Real outputs of the decoder we train later. Step 2 gives a probability per pixel (a grey image). Step 3 flips a coin per pixel. Most papers show step 2 as "the sample" because it looks cleaner.

If we had this decoder, generating would be trivial. The whole difficulty is training it.
