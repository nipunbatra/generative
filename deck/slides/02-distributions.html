Learn a distribution from examples, then sample from it

We have seen what generators can do. Before any network, the whole idea on one number: what does "learning" mean, and how do we then make new samples?

What are we trying to do?

Examples in, a model out, new examples from the model

1 · Learn

Choose the model's parameters $\theta$ so that the examples we have are probable under it.

2 · Generate

Draw new samples from the learned model $p_\theta$.

This is the frame for the whole lecture. Every model today does these two steps; they differ in what the model is and how the learning is done.

Bottom row: the 1-D toy version we use for the next few slides. Same task, one number per example instead of 784 pixels.

Our toy data

200 numbers from a recipe we keep hidden

The model sees only these 200 numbers, not the recipe. Goal: learn from them, then produce a 201st that looks like it belongs.

The hidden recipe (reveal at the end of the part): flip a fair coin; heads, draw from 𝒩(−2, 0.5²); tails, from 𝒩(2, 0.5²). Students should just see two clumps.

Ask for ideas. "Pick an existing number" copies, it does not generate. "Use the average" is next.

A tempting answer

The average is a terrible sample

The mean is a number that almost never occurs. Generating needs the whole spread of the data, not one summary of it.

This is why "train a network with squared error to output an image" gives blurry averages.

Our first model: one Gaussian · how it scores a number

How probable is $x = 1.5$ under a bump at 2?

$$\N(x;\mu,\sigma^2) = \frac{1}{\sigma\sqrt{2\pi}}\,\exp\!\Big(-\frac{(x-\mu)^2}{2\sigma^2}\Big)$$
$$\frac{x-\mu}{\sigma} = \frac{1.5 - 2}{0.5} = -1$$
$$\exp\!\big(-\tfrac12\cdot(-1)^2\big) = e^{-0.5} = {{gauss_15.expo}}$$
$$\frac{1}{0.5\sqrt{2\pi}} = {{gauss_15.norm}} \qquad\Rightarrow\qquad {{gauss_15.norm}}\times{{gauss_15.expo}} = \mathbf{ {{gauss_15.value}} }$$

The model's two parameters, $\mu$ and $\sigma$, decide how high the curve is at every $x$. Higher means more probable.

The formula has two parts: how many standard deviations x is from the centre (squared, inside the exponent), and a constant that makes the total area 1.

A density is a height, not a probability: it can exceed 1 for a narrow bump. Only areas are probabilities. For comparing parameter choices, heights are what we need.

Step 1 · Learn

Score a choice of $\mu, \sigma$ on all 200 numbers

$$\log p_\theta(\text{data}) = \sum_{i=1}^{200} \log \N(x_i;\mu,\sigma^2), \qquad \theta = (\mu, \sigma)$$
$\log p = {{cand.a.ll}}$
$\log p = {{cand.b.ll}}$
$\log p = {{cand.c.ll}}$

Learning = keep the $\theta$ with the highest score. That is maximum likelihood, the same rule that trained the name model.

Why the log? The likelihood is a product of 200 heights, a tiny number. The log turns it into a sum, and the best θ is the same.

Left: a narrow bump on the right clump. It fits those points perfectly, but every point on the left clump is 8 standard deviations away, so the score collapses. Middle: a narrow bump in the gap misses every point by about 4 standard deviations, which costs less in total. Right: the best single Gaussian, wide enough to cover both clumps.

Step 1 · Learn, then Step 2 · Generate

The best Gaussian has a formula; then we sample from it

$$\hat\mu = \frac1N\sum_{i=1}^{N} x_i = {{toy.mean}} \qquad \hat\sigma^2 = \frac1N \sum_{i=1}^{N} (x_i-\hat\mu)^2 = {{toy.var}}$$
$$x_{\text{new}} = \hat\mu + \hat\sigma\,\eps,\quad \eps \sim \N(0,1)$$

Setting the derivative of the score to zero gives these two numbers: the same answer as the third candidate.

Step 2: {{toy.gauss_samples_in_gap}} of 30 samples land in the empty gap. Learning worked; the model was too simple.

Students derived the Gaussian maximum-likelihood estimates in the probability lectures: the sample mean and the 1/N variance.

Lesson: optimisation worked perfectly; the model family could not describe two clumps. Better optimisation cannot fix that.

The same fit, in PyTorch

Learning = gradient descent on the negative log-likelihood

x = torch.tensor(data)                  # the 200 numbers
mu        = torch.tensor(1.0, requires_grad=True)
log_sigma = torch.tensor(0.0, requires_grad=True)
opt = torch.optim.Adam([mu, log_sigma], lr=0.05)

for step in range(300):
    dist = Normal(mu, log_sigma.exp())
    loss = -dist.log_prob(x).mean()
    opt.zero_grad(); loss.backward(); opt.step()

x_new = dist.sample((30,))              # step 2: generate

The parameters $\theta = (\mu, \log\sigma)$, started anywhere. We learn $\log\sigma$ so that $\sigma = e^{\log\sigma}$ is always positive.

The loss is the score from the last slide with a minus sign, averaged: $-\frac1N\sum_i \log\N(x_i;\mu,\sigma^2)$.

The update: nudge $\mu$ and $\log\sigma$ downhill, 300 times. The same loop trains every network in this course.

Result: $\mu = {{gd.mu}}$, $\sigma = {{gd.sd}}$, exactly the formula's answer. Then sample is step 2.

Real run (scripts/make_figures_extra.py). Point out that nothing here is specific to Gaussians: swap Normal for any distribution with a log_prob, and the loop is unchanged. That is how we will fit the two-bump model, and later the VAE.

A richer model: tell a story

Hidden choice first, then the number

This is how we will generate: run the two steps. The coin is never written down in the data, so it is a hidden (latent) variable $z$.

Read the recipe aloud: flip a coin, pick that bump, draw a number from it. Two simple steps make two clumps, which one Gaussian could not.

How the new model scores a number

To score $x$, add up every way it could have been made

$$p(x) = \underbrace{\tfrac12\,\N(x;-2,0.5^2)}_{\text{made by bump A}} + \underbrace{\tfrac12\,\N(x;\,2,0.5^2)}_{\text{made by bump B}} = \sum_{z} \cz{p(z)}\,\cdec{p(x\mid z)}$$
$$\text{at } x=1.5:\quad \tfrac12\cdot 0.000 + \tfrac12\cdot {{gauss_15.value}} = 0.242$$

One hidden coin flip made the model rich enough: the samples now fall in the bumps, not in the gap.

Read the formula aloud: probability of x through bump A plus probability of x through bump B, each weighted by how likely that bump is. Summing over the hidden choice is called marginalising it out.

The A-bump contributes about 9 × 10⁻¹² at x = 1.5 (½ × 1.8 × 10⁻¹¹): 7 standard deviations away.

Fitting $K$ bumps in PyTorch

Same loop, a richer log_prob

logits = torch.zeros(K, requires_grad=True)   # bump weights
means  = torch.randn(K, requires_grad=True)
log_sd = torch.zeros(K, requires_grad=True)

def log_p(x):                                # log p(x), shape [N]
    comp = Normal(means, log_sd.exp()).log_prob(x[:, None])   # [N, K]
    return torch.logsumexp(log_softmax(logits) + comp, dim=1)

loss = -log_p(x).mean()        # then the same 3-line update

Three parameters per bump: a weight, a centre, a width. softmax turns the weights into probabilities that sum to 1.

Every number under every bump: $\log p(x_i\mid z = k)$ for all $i$ and $k$, a table of $N \times K$ log-densities.

The sum over the hidden choice: $\log\sum_k p(k)\,p(x\mid k)$. logsumexp does it without underflow.

Training is unchanged. With $K = 2$ it finds centres {{mixK.1.means.0}} and {{mixK.1.means.1}}, widths {{mixK.1.sds.0}} and {{mixK.1.sds.1}}.

The hidden recipe was centres −2 and 2, widths 0.5, weights ½ each. Gradient descent recovers it from 200 numbers alone. Compare with the formula slide: there is no closed form for a mixture, so here gradient descent is not just a convenience, it is the method.

Step 2 · Generate, from the two-bump fit

Sampling runs the story: choose a bump, then a number

weights = softmax(logits)
k = torch.multinomial(weights, 1000,
                      replacement=True)    # the coin
x_new = means[k] + log_sd.exp()[k] * torch.randn(1000)

Step 1: pick a bump for each sample, with the learned weights.

Step 2: draw a number from that bump: its centre plus its width times standard noise.

1,000 new numbers that follow the data, and none of them is a copy of a training number.

But how many bumps should we fit?

More bumps always fit the training data better

1, 2, 3, 4 bumps, each fitted with the same loop. The training score rises every time. So which one do we keep?

The 3- and 4-bump fits spend their extra bumps on a narrow spike or a small shoulder: a tiny bump of width 0.05 at 3.27 in the 4-bump fit. Training log-likelihood: {{mixK.0.train}}, {{mixK.1.train}}, {{mixK.2.train}}, {{mixK.3.train}}.

Score on data the fit has never seen

New data decides: two bumps

Draw 200 new numbers from the same hidden recipe and score each fit on them.

1 → 2 bumps: ${{mixK.0.held}} \to {{mixK.1.held}}$ per number. A real improvement.

3 or 4 bumps: the training score creeps up, the new-data score does not. The extra bumps fit noise in the 200 training numbers.

Choose the size of a model by how well it scores data it has not seen. That holds for bumps, and for networks.

Step 1 · Learn, looked at closely

Hidden in the fit: which bump made each point?

If we knew the coin for every point

fitting is easy: average the A-points for bump A's centre, the B-points for bump B's.

We don't, so ask for each point

given this $x$, how probable is it that bump B made it? That is $p(\mathrm{B}\mid x)$.

Running the story backwards, from a number to its likely hidden cause, is called inference. The gradient descent we just ran was doing it all along: four slides on, we will see where.

Build 3: each of the 200 points coloured by p(B | x), computed on the next slide. Points in the middle are grey: unsure.

For the curious: alternating "guess the bump" and "refit the bumps" is the EM algorithm. We will not need its details; the point is that learning a hidden-variable model needs this backwards step.

The backwards step, worked by hand

You see $x = 0.1$. Which bump made it?

$$p(\mathrm{B}\mid x) = \frac{p(\mathrm{B})\,p(x\mid\mathrm{B})}{p(x)} = {{bayes01.post_b}}$$

Bayes' rule is just this table: multiply, then divide by the total. Note the total is exactly the $p(x)$ of the two-bump formula.

Build by build: the two likelihoods (both tiny: 0.1 is far from both centres, but closer to B), multiply by the prior, add to get p(x), divide.

The tiny numbers do not matter, only their ratio. Important for later: the backwards step needs p(x), the sum over all hidden values.

Do it for every $x$

The backwards step, as a curve

Repeat the table for every $x$ and plot $p(\mathrm{B}\mid x)$.

Far right: certainly B. Far left: certainly A. Near 0: unsure.

For these two bumps the curve is exactly $\mathrm{sigmoid}(16x)$: a logistic regression in disguise.

These are the colours on the 200 points two slides ago.

Derivation of the sigmoid if asked: the log ratio of the two likelihoods is [(x+2)² − (x−2)²]/(2·0.25) = 16x, and the equal priors cancel.

The backwards step, in one line

Posterior = softmax of (log prior + log likelihood)

log_joint = log_softmax(logits) + Normal(means, log_sd.exp()).log_prob(x)   # [K]
posterior = softmax(log_joint)                 # divide by the total: Bayes

With the fitted bumps, at $x = 0.1$: $p(\mathrm{A}\mid x) = {{mix_post01.0}}$, $p(\mathrm{B}\mid x) = {{mix_post01.1}}$. (With the true recipe it was {{bayes01.post_b}}: the fitted bumps are slightly different.)

Softmax is "exponentiate, then divide by the total": exactly the last column of the Bayes table.

Why learning needs the backwards step

The gradient of $\log p(x)$ is weighted by the posterior

$$\frac{\partial \log p(x)}{\partial \mu_k} \;=\; \hl{p(k\mid x)}\;\cdot\;\frac{x - \mu_k}{\sigma_k^2}$$

At $x = 0.1$: bump B's centre is pulled by ${{pull.rb}} \times (0.1 - 2)/0.25 = {{pull.gb}}$, bump A's by ${{pull.ra}} \times (0.1 + 2)/0.25 = {{pull.ga}}$.

Each point pulls each bump in proportion to how likely that bump made it. Learning needs the posterior for every point: a 2-row table here, an intractable patch for images.

Derivation, one line: p(x) = Σ_k π_k N(x; μ_k, σ_k²), so ∂ log p / ∂μ_k = π_k N(x; μ_k, σ_k²) / p(x) · (x − μ_k)/σ_k², and the first factor is Bayes' rule for p(k | x).

Numbers use the true recipe (centres ±2, widths 0.5, weights ½). This is the slide to come back to in Part 3: with a decoder instead of two bumps, the same gradient needs p(z | x) over a whole plane of codes.

Prior, likelihood, evidence, posterior

Generating uses the prior and the likelihood. Learning needs the evidence and the posterior.

Keep these four colours in mind: amber for z and the prior, teal for the decoder and the likelihood, blue for observed data, purple for the posterior.
