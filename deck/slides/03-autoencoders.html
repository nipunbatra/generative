The obvious idea

Keep the decoder, feed it a random code

The decoder turns codes into digits. So a random code should give a random digit. Right?

Let students commit to a prediction before the next slide.

What is a "random code"?

$z \sim \N(0, I)$: two independent bell curves

Draw $z_1$ from a standard bell curve $\N(0, 1)$: mean 0, spread 1. Draw $z_2$ the same way, independently.

Together that is written $\N(0, I)$: the 0 says the centre is $(0, 0)$; the I (identity matrix) says each number has spread 1 and the two do not depend on each other.

500 draws, plotted: most land within 2 of the origin, almost none beyond 3.

Why this choice? It is the simplest distribution we can sample from. The decoder, though, was never told about it.

In 2-D the fraction inside radius r is 1 − exp(−r²/2): 39% within 1, 86% within 2, 99% within 3. Students often expect 68% within radius 1, which is the 1-D number.

What actually comes out

Random codes give scribbles

ten codes drawn from $\N(0, I)$ in 16 dimensions, through the trained decoder

The decoder only ever saw codes made by the encoder. Where do those codes live?

Nothing in the training loss mentioned 𝒩(0, I). The encoder was free to put codes anywhere: shifted, stretched, with large gaps. A random code lands somewhere the decoder never trained on.

We cannot plot 16 dimensions, so next we retrain the same autoencoder with a 2-number code and look.

Where 5,000 test digits land

Same digits cluster together. Nobody asked for that; it just helps reconstruction.

Look at the axes: $z_1$ runs from {{ae_range.0.0}} to {{ae_range.0.1}}, $z_2$ from {{ae_range.1.0}} to {{ae_range.1.1}}. Nothing made the codes stay near the origin.

The code space has an arbitrary shape, scale and position.

The encoder never saw labels. Clustering by digit emerges because similar images are cheapest to decode from nearby codes.

Overlay random codes

Random draws all land in one small spot

Now add 150 random codes from $\N(0, I)$ (orange), the kind we fed the decoder two slides ago. Dashed circles: radius 1 and 2. On this map they all fall into one small crowded patch.

ten of them decoded: some digits, some smudges

And we can never generate a 1: the 1s live near $z_1 \approx 20$.

To sample, we need to know where the codes are, and every point there must decode to something sensible.

Two separate failures. (1) Coverage: the region where we sample does not match where codes live, so whole classes are missing. (2) Holes: between clusters the decoder was never trained, so it produces smudges.

What we want instead

Encode to a cloud, not a point

Known: pull every cloud towards $\N(0, I)$, so random draws land on real codes.
Smooth: every point in a cloud must decode to that image, so neighbourhoods are meaningful.

If the encoder outputs a small region instead of a point, and the decoder must reconstruct x from any point in that region, then the space between nearby codes gets trained. Pulling all regions towards 𝒩(0, I) makes the space compact and tells us where to sample.

That is the variational autoencoder in one picture. The rest of the theory explains why this is the principled loss, not just a trick.

What we did, and what comes next

What we did

  1. An encoder squeezes an image into a short code; a decoder rebuilds it. The image is its own target.
  2. Random codes from $\N(0, I)$ decode to scribbles.
  3. The codes spread over an arbitrary range, and the decoder never saw the space between them.
  4. The wish: encode each image to a cloud, and keep every cloud near $\N(0, I)$.
