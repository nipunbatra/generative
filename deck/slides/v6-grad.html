Climbing the ELBO with samples and gradients

The ELBO is an average under $q$. Estimate it from a few draws (Part 3), then climb it by gradient ascent on $m$ and $s$. One step needs care: a gradient through a random draw.

Step 1: estimate the ELBO from draws

Three lines, using only things we can compute

def log_joint(z):                # Part 2's one line
    return (Normal(0, 1).log_prob(z)
            + 8 * F.logsigmoid(z) + 2 * F.logsigmoid(-z))

q = Normal(0.0, 1.0)                 # start: q is the prior
z = q.sample((S,))                   # S draws from q
elbo = (log_joint(z) - q.log_prob(z)).mean()

The joint: prior times likelihood, in logs. Any $z$, one line.

Draws from $q$: easy, because we chose $q$.

The ELBO's definition, averaged: $\E_q[\log p(x,z) - \log q(z)]$.

Step 2: the gradient. The subtle part.

The gradient of an average whose draws move

$$\frac{\partial}{\partial m}\;\E_{z\sim\N(m,\,s^2)}\big[f(z)\big] \;=\; ?$$

Move $m$ and the draws themselves move. The randomness depends on what we differentiate.

A toy with a known answer (Part 3's): $q = \N(\mu, \sigma^2)$ with $\mu = 1$, $\sigma = 0.5$, and $f(z) = z^2$. Since $\E[z^2] = \mu^2 + \sigma^2$, the exact gradient is $\dfrac{\partial}{\partial\mu}(\mu^2 + \sigma^2) = 2\mu = 2$.

Two standard ways to estimate it from draws: the score function, and reparameterisation.

We write μ, σ for the toy and m, s for the coin's q; they play the same role. The VAE lecture uses μ, σ for the encoder's outputs.

Way 1

The score function (the log-derivative trick)

$\dfrac{\partial}{\partial\mu}\displaystyle\int q_\mu(z)\,f(z)\,dz$$=$$\displaystyle\int \frac{\partial q_\mu(z)}{\partial\mu}\,f(z)\,dz$ $f$ does not depend on $\mu$; only $q$ does $=$$\displaystyle\int q_\mu(z)\,\frac{\partial \log q_\mu(z)}{\partial\mu}\,f(z)\,dz$ $\partial q = q\,\partial\log q$: multiply and divide by $q$ $=$$\displaystyle\E_{z\sim q}\Big[f(z)\,\frac{z-\mu}{\sigma^2}\Big]$ an average under $q$ again; for a Gaussian, $\partial\log q/\partial\mu = (z-\mu)/\sigma^2$

Estimate it with draws: average $f(z)\,(z-\mu)/\sigma^2$. Works for any $q$ and any $f$, even an $f$ you cannot differentiate.

Also called REINFORCE (from reinforcement learning, where f is a reward you cannot differentiate). ∂ log q / ∂μ is called the score of q.

Way 2

Reparameterisation: stretch and shift standard noise

$$z = \mu + \sigma\eps,\ \eps\sim\N(0,1) \;\;\Rightarrow\;\; \E_{z\sim q}\big[f(z)\big] = \E_{\eps}\big[f(\mu + \sigma\eps)\big] \;\;\Rightarrow\;\; \frac{\partial}{\partial\mu}\E = \E_{\eps}\big[f'(\mu + \sigma\eps)\big]$$

Now the randomness, $\eps$, does not depend on $\mu$. The parameter sits inside $f$'s argument, and the ordinary chain rule applies.

Follow the red dot: ε = −0.4, scaled by σ = 0.5 to −0.2, shifted by μ = 1 to 0.8. Same distribution as before; the draw is now a deterministic function of (μ, σ, ε).

Part 3's sampling line, z = mu + sigma * torch.randn(...), was already reparameterised. That is why it matters how you write a draw.

One draw, both ways

$\eps = -0.4$, so $z = 1 + 0.5\times(-0.4) = 0.8$

Score function

$$f(z)\,\frac{z-\mu}{\sigma^2} = 0.64\times\frac{-0.2}{0.25} = {{vik.grad.one_sf}}$$

Reparameterisation

$$f'(z)\,\frac{\partial z}{\partial\mu} = 2z\times 1 = {{vik.grad.one_rep}}$$

The exact answer is 2. One draw says $-0.51$ one way and $1.6$ the other. Both are right on average; how noisy is each?

On the coin's ELBO, the same story

Reparameterisation is the low-noise choice

$\partial\,\ELBO/\partial m$ at $q = \N(0, 1)$. Exact: {{vik.grad.coin_exact}} (push $m$ up, towards more heads).

Spread of a one-draw estimate: {{vik.grad.coin_sf_sd}} (score function) vs {{vik.grad.coin_rep_sd}} (reparameterisation).

Both shrink like $1/\sqrt{S}$, but the score function needs about {{vik.grad.coin_ratio}}× more draws to match.

That is why VI with Gaussians, and the VAE, use reparameterisation. The score function returns when $z$ is discrete and $f'(z)$ does not exist.

Reparameterised one-draw gradient: d/dm log p(x, m + sε) = −z + 8 − 10·sigmoid(z) at z = m + sε. Score-function one-draw gradient: (log p(x, z) − log q(z)) (z − m)/s². Both average to {{vik.grad.coin_exact}}.

In PyTorch (as in the PML course's VI notebook)

rsample, not sample

mu    = torch.tensor(1.0, requires_grad=True)
sigma = torch.tensor(0.5, requires_grad=True)
q = Normal(mu, sigma)

z = q.sample()
(z**2).backward()
# RuntimeError: element 0 of tensors does not require grad
#               and does not have a grad_fn

z = q.rsample()                # = mu + sigma * eps, eps ~ N(0, 1)
(z**2).backward()
mu.grad                        # 2 z: one reparameterised draw

The toy again: $\mu = 1$, $\sigma = 0.5$, $f(z) = z^2$.

sample() returns a plain number: the graph is cut at $z$, so no gradient can reach $\mu$.

rsample() ("reparameterised sample") draws $\eps$ and returns $\mu + \sigma\eps$: same distribution, but a graph from $z$ back to $\mu$ and $\sigma$.

Writing mu + sigma * torch.randn(...) by hand does exactly the same thing.

The error text is what PyTorch prints (checked with torch 2.13). The PML notebook shows the same three versions: the default sample, the reparameterisation done by hand, and rsample.

Variational inference for the coin

The whole loop: two numbers, gradient ascent on the ELBO

def neg_elbo(q, S=10):
    z = q.rsample((S,))                       # S reparameterised draws
    return -(log_joint(z) - q.log_prob(z)).mean()

m     = torch.tensor(0.0, requires_grad=True)   # start at the prior
log_s = torch.tensor(0.0, requires_grad=True)   # s = exp(log_s) = 1
opt = torch.optim.Adam([m, log_s], lr=0.05)

for step in range(400):
    loss = neg_elbo(Normal(m, log_s.exp()))
    opt.zero_grad(); loss.backward(); opt.step()

The loss: minus the ELBO estimate of two slides ago, now with rsample so gradients flow.

Only $q$ is learned: two numbers. We learn $\log s$ so that $s$ stays positive.

The same three-line loop as fitting any model. 400 steps of 10 draws each: $m = {{vik.run.table.5.m}}$, $s = {{vik.run.table.5.s}}$. The best Gaussian: ${{vik.vi.m}}$, ${{vik.vi.s}}$.

Real run (scripts/make_figures_vi.py, the part_vi function) with this loop. neg_elbo has the same shape as the PML notebook's function of the same name; the only change is a Gaussian q over z instead of a Beta q over θ (that version is the last slide of this part).
